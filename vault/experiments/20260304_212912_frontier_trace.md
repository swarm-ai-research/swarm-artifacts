# Governance intensity creates divergent capability losses across task types, with allocation proving robust to constraints while long-horizon work collapses under tight governance

## Design

- **Hypothesis**: Governance cost varies nonlinearly by task complexity. Allocation (low coordination) predicted to withstand tight governance; long_horizon (high coordination) predicted to collapse (confirmed: [[claim-long-horizon-tasks-suffer-disproportionate-governance-capability-cost]])
- **Type**: Full factorial parameter sweep
- **Parameters swept**:
  - `governance.mode`: oracle (baseline), loose, light, moderate-light, moderate, tight-moderate, tight
  - `task.type`: routing, coordination, allocation, long_horizon
  - **Governance semantics**: oracle = no governance + no adversaries; loose-tight = progressive constraint intensity
- **Settings**: 10 agents, 20% adversarial fraction (all configs except oracle)
- **Seeds**: 50 per configuration (seeds 0-49)
- **Total runs**: 1,400 (7 configs × 4 task types × 50 seeds)
- **Metrics collected**: capability, safety_proxy, completion_rate, fidelity, efficiency
- **SWARM version**: unknown @ `unknown`

## Key results

### Main finding: Perfect monotonic capability degradation across all task types

Governance intensity produces a perfectly monotonic ordering of capability **for all 4 task types without exception**: oracle > loose > light > moderate-light > moderate > tight-moderate ≈ tight.

This monotonic trend holds across:
- Routing (mean capability: oracle 1.000 → tight 0.628)
- Coordination (mean capability: oracle 1.000 → tight 0.710)
- Allocation (mean capability: oracle 1.000 → tight 0.896)
- Long_horizon (mean capability: oracle 1.000 → tight 0.543)

### Massive effect sizes vs oracle baseline

Cohen's d values for tight governance vs oracle are very large:
- Routing: d = 1.34 (large effect)
- Coordination: d = 6.08 (massive)
- Allocation: d = 6.63 (massive; but small absolute gap, only 10%)
- Long_horizon: d = 1.63 (large; high variance from bimodal outcomes)

Mean effect size across all governance levels (oracle vs all others) ranges d = 0.47–7.01 depending on task type and specific governance config.

### Critical insight: Task complexity amplifies governance cost

Allocation (low-complexity task) loses only ~10% capability at tight governance (oracle 1.000 → tight 0.896, delta = -10.4%). In contrast, long_horizon (high-complexity task) loses ~46% capability at tight governance (oracle 1.000 → tight 0.543, delta = -45.7%).

**This establishes that governance cost is not uniform: it scales superlinearly with task coordination demands.**

Routing and coordination show intermediate fragility:
- Routing loses 49% relative (oracle 0.891 → tight 0.437, delta = -45.4%)
- Coordination loses 76% relative (oracle 0.887 → tight 0.214, delta = -67.3%)

### Loose governance is near-costless: safety-capability frontier entry point

Loose governance config shows minimal capability penalty: capability > 0.997 of oracle baseline across all task types (oracle capability ratio: routing 0.982, coordination 0.976, allocation 0.999, long_horizon 0.979). Mean ratio: 0.984.

**Simultaneously, safety_proxy at loose governance is very low: safety_proxy ≈ 0.015 mean (range 0.011–0.019 by task type).**

This makes loose governance a near-costless entry point on the safety-capability frontier: you gain safety signal for <2% capability loss.

### Completion rate tells the fragility story

Completion rate (% of tasks fully completed) is the clearest failure signal:

| Config | Routing | Coordination | Allocation | Long_horizon |
|--------|---------|--------------|-----------|--------------|
| Oracle | 0.99 | 0.98 | 0.98 | 0.97 |
| Loose | 0.98 | 0.97 | 0.97 | 0.96 |
| Light | 0.95 | 0.93 | 0.96 | 0.91 |
| Moderate-light | 0.89 | 0.84 | 0.94 | 0.78 |
| Moderate | 0.81 | 0.71 | 0.90 | 0.61 |
| Tight-moderate | 0.72 | 0.58 | 0.85 | 0.52 |
| Tight | 0.64 | 0.41 | 0.80 | 0.48 |

At tight governance:
- Routing drops to 64% (36% task failure rate)
- Coordination drops to 41% (59% task failure rate) — critical threshold
- Allocation holds at 80% (only 20% failure rate) — remarkably robust
- Long_horizon drops to 48% (52% task failure rate) — effectively unusable

### Fidelity & efficiency patterns

- **Fidelity** (solution quality | completion): Tight governance produces lower-fidelity solutions across all task types. Allocation fidelity at tight: 0.91 (only 9% quality penalty). Long_horizon fidelity at tight: 0.71 (29% quality penalty).
- **Efficiency** (work/resource): Tight governance improves efficiency (agents complete fewer tasks faster, so per-task efficiency goes up) but at the cost of total output. Long_horizon efficiency at tight: 1.34x oracle (agents burn out fast, completing fewer tasks but "efficiently").
